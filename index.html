Assignment Overview

Practical Assignment №2 extends the existing WebGL stereo rendering project with a tangible interface. A smartphone is used as a physical controller for rotating the analytical surface in the virtual scene.

According to Variant 14, the input device is based on a hardware magnetometer. The browser provides a processed compass-like orientation value, so the phone controls the model by changing its yaw angle around the vertical axis.

The previous rendering pipeline remains unchanged: Sievert's Surface is still rendered with indexed triangles, normal mapping, specular mapping, Phong per-pixel lighting, an animated point light, stereo anaglyph rendering, and wireframe overlay.

Connection Scheme

Smartphone browser
      ↓ DeviceOrientation / compass heading
HTTPS tunnel page
      ↓ POST /sensor
Local Node.js server
      ↓ GET /sensor
WebGL scene on laptop
      ↓ yaw rotation of the model

The phone controller is opened through an HTTPS tunnel because mobile browsers require a secure context for sensor access. The WebGL scene is opened locally through localhost, which avoids unstable tunnel polling and reduces delay.

Phone Controls

Enable sensors — starts reading phone orientation.
Calibrate zero — stores the current direction as the reference angle.
Phone rotation — rotates the surface around the vertical axis.

Interactive WebGL Scene

The smartphone acts as an external physical controller, while mouse rotation, stereo rendering, anaglyph mode, and rendering parameters remain available.

  • Smartphone orientation — tangible yaw control of the model
  • M — toggle phone-based control
  • Mouse drag — manual trackball rotation
  • T — toggle stereo anaglyph / mono rendering
